# Synthetic sky-image set (24 windows, 2023) — candidate for shipping in place of SIRTA data

This is **synthetic data**, not SIRTA observations. The 64×64 RGB images are generated by a conditional
diffusion model trained on real SIRTA 2023 sky images (SIRTA_preprocessing's dataloader/training pipeline);
the underlying dataset is SIRTA's, and we acknowledge SIRTA for it:

> Haeffelin, M., et al. (2005). SIRTA, a ground-based atmospheric observatory for cloud and aerosol
> research. *Annales Geophysicae*, 23(2), 253–275. https://doi.org/10.5194/angeo-23-253-2005

The model's image decoder is the `CompVis/stable-diffusion-v1-4` VAE (Hugging Face `diffusers`), licensed
CreativeML Open RAIL-M.

**Irradiance values (`I` in `synthetic_data_2023.csv`) are invented** — smooth clear-sky-index curves
`k(t)` times a computed clear-sky `Iclr` (`I = k · Iclr`), not measurements of any kind. **Timestamps are on
odd minutes** (SIRTA's real observations are on even minutes), so no frame here coincides with, or is meant
to be compared against, a real observation at that exact time.

- **Generator:** commit `3b7a03291b41b802872e50f0a1d161208cf071cc` (clean tree); checkpoint `context_model-1535.pth`, sha256
  `e7b0fe4b205c8e0ba3d01eded036eae0e1143c84deeecb27652f8a57bdca4e15`.
- **Windows:** 24, 8 each over 3 days in different seasons (`2023-02-15`, `2023-07-19`, `2023-10-11`), none a
  real SIRTA sample day. 16 frames each (y0−16 min … y0+14 min, 2-minute steps), 384 rows. Every frame has
  `Iclr > 100 W/m²`; windows within a day do not overlap.
- **Cases:** 6 clear (k 1.02–1.08), 6 cloudy (k 0.2–0.5), 4 partly cloudy (k 0.6–0.85), 4 up-ramps and 4
  down-ramps (Δk ≥ 0.4 over the 8 target frames), assigned to windows with a recorded seed (20261004).
- **Noise mode `independent`:** window *w* uses seed `2000 + w`; one call per window, batch of the 16
  labels, each frame gets a different noise slot (0–15).
- **Windows (day, y0, case):**
  `2023-02-15`: 09:59 cloudy, 10:53 cloudy, 11:47 partly, 12:41 down, 13:33 up, 14:27 clear, 15:21 clear,
  16:15 partly.
  `2023-07-19`: 08:27 cloudy, 10:01 down, 11:37 up, 13:11 partly, 14:47 cloudy, 16:21 up, 17:57 clear,
  19:31 clear.
  `2023-10-11`: 10:01 clear, 11:03 down, 12:05 partly, 13:07 cloudy, 14:11 up, 15:13 cloudy, 16:15 down,
  17:17 clear.
- **Not-a-copy check:** nearest-neighbour pixel distance against the real training corpus (134,312 frames);
  6 of 384 frames (all uniform clear/overcast, the lowest-texture cases) fell just below the real-vs-real
  baseline's 5th percentile. If the synthetic frames were no closer to real frames than real frames are to
  each other, about 5% of them would fall below that threshold by construction; 1.6% did, so the synthetic
  frames are not unusually close to any training image. The closest ones are uniform clear or overcast
  skies, which look alike in any case.
- `test_subset_ids.csv` / `test_subset_indices.npy` select the 24 windows this folder builds by timestamp
  (see `eval/make_subset_indices.py`); both are included here.

## Expected scores — a consistency check, not a performance result

`python eval/check_synthetic.py` runs every method that supports this set and checks the result against the
table below (`prediction_samples/expected_synthetic.csv`), so you can confirm each one still runs correctly
on your machine. Because this set's irradiance is invented, these scores say nothing about how the methods
compare on real data, and the ranking below is not the paper's (Table 2). Every row is reported EXACT
(bit-identical to the table below), CLOSE (within its tolerance) or FAIL. Tolerances were measured on one
GPU by changing its own numerical settings (TF32, cuDNN algorithm choice), then given a floor of 0.5% of
each expected score (with a small absolute floor for FS/CRPSS, which can sit near zero) so a correct run on
different hardware or software still passes. EXACT and CLOSE both mean the method ran correctly; a FAIL,
especially by a wide margin, points to a problem with the setup (weights, config or data) rather than
ordinary numerical noise. SkyGPT never reports EXACT: its sampler is unseeded, so it is always CLOSE or
FAIL. Per-row tolerances are in `prediction_samples/expected_synthetic.csv`'s `*_tol` columns. Xiong does
not appear: it needs a non-empty validation split (see `PORTING_NOTES.md`), which this set leaves empty by
design.
